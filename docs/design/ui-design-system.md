# KinetiQ UI Design System

## Purpose

Defines the rules for every UI component used throughout the application.

---

# Layout Philosophy

The interface should be spacious.

Information dense.

Easy to scan.

Never overwhelming.

---

# Grid

Desktop

12-column responsive grid.

Mobile

Single-column layout.

Tablet

Adaptive layout.

---

# Border Radius

Cards

16px

Buttons

12px

Inputs

12px

Dialogs

20px

Badges

9999px

---

# Shadows

Prefer subtle elevation.

Avoid dramatic shadows.

Dark mode relies more on contrast than shadows.

---

# Cards

Cards are the primary layout unit.

Every card should include:

- consistent padding
- title
- optional description
- content
- optional actions

Avoid deeply nested cards.

---

# Tables

Tables should prioritize readability.

Use:

- zebra striping only if necessary
- subtle row hover
- compact spacing
- left-aligned text
- right-aligned numeric values

---

# Buttons

Primary

Orange

Secondary

Neutral

Ghost

Transparent

Danger

Red

Avoid multiple primary buttons inside the same viewport.

---

# Forms

Always:

- clear labels
- helper text when needed
- validation below fields
- consistent spacing

---

# Navigation

Desktop

Left sidebar.

Mobile

Bottom navigation.

Never mix navigation styles unnecessarily.

---

# Icons

Use Lucide exclusively.

Do not mix icon libraries.

---

# Motion

Animations should be subtle.

Duration

150–250ms

Use:

- fade
- scale
- slide

Avoid:

- bounce
- spin
- exaggerated movement

---

# Charts

Charts should emphasize trends.

Avoid visual clutter.

Use the accent color sparingly.

---

# Empty States

Every empty state should:

Explain why it is empty.

Explain what the user can do next.

Provide one clear action.

---

# Loading States

Prefer skeleton loaders.

Avoid spinners unless absolutely necessary.

---

# Accessibility

Keyboard navigation.

Visible focus states.

Sufficient contrast.

ARIA support.

Semantic HTML.

Never sacrifice accessibility for aesthetics.
